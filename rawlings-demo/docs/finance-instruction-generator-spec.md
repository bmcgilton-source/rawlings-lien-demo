# Finance Instruction Generator — Demo Specification

## 1. Purpose

Add a visible, auditable final artifact to the lien lifecycle demonstration.

After payment has been reconciled and disbursement has been approved, an authorized user generates a Finance instruction CSV from the Lien record. Salesforce attaches the file to the Lien and shows the result immediately.

This proves that Salesforce can:

- Convert the completed workflow into a controlled downstream instruction.
- Validate that collection and allocation are complete before handoff.
- Preserve the exact artifact sent to Finance.
- Record who generated it and when.
- Support a later Finance integration without pretending one exists in the prototype.

Salesforce does **not** move funds in this prototype. It generates the instruction Finance would consume.

## 2. Demo outcome

The presenter completes `Complete Lien Journey`, returns to the closed Lien, and selects:

**Generate Finance Instruction**

Salesforce:

1. Validates that the lien is eligible.
2. Generates a one-row CSV.
3. Attaches the CSV to the Lien as a Salesforce File.
4. Records the generated timestamp and generating user.
5. Displays the instruction values in the action.
6. Shows a success message containing the filename.

The presenter then opens the Lien’s Files related list and points to the preserved Finance instruction.

## 3. Scope

### Included

- One Finance instruction per button click.
- One lien per instruction file.
- CSV generation.
- Salesforce File attachment to the Lien.
- Eligibility and allocation validation.
- Generated timestamp and user.
- Clear success and error states.
- Apex unit tests.
- Lien quick action.
- Demo talk track and reset procedure.

### Excluded

- Direct Finance-system integration.
- SFTP, API, email, or middleware delivery.
- Actual movement of funds.
- Multi-lien settlement batches.
- Approval chains beyond the existing guided Flow.
- General ledger account mapping.
- Bank account or payment-instruction data.
- PGP encryption.
- File acknowledgment from Finance.
- Retry, delivery, or integration-job tracking.

## 4. User story

> As an authorized lien operations user, after payment is reconciled and disbursement is approved, I want to generate a Finance instruction from the Lien so the approved allocations can be handed to Finance and the exact instruction is retained with the recovery record.

## 8. CSV format

### Filename

Use:

```text
Finance_Instruction_<Claimant_ID>_<YYYYMMDD-HHmmss>.csv
```

Example:

```text
Finance_Instruction_CLM-00004_20260728-142530.csv
```

Sanitize the claimant ID before using it in a filename. Replace characters other than letters, numbers, hyphens, and underscores.

### Encoding

- UTF-8
- Comma-delimited
- CRLF or LF line endings
- One header row
- One data row

### Columns

Use this exact order:

```text
Instruction_ID,
Settlement,
Lien_ID,
Claimant_ID,
Claimant_Name,
Agreed_Amount,
Recovery_Amount,
Remittance_Amount,
Payment_Variance,
Health_Plan_Allocation,
Rawlings_Allocation,
Disbursement_Status,
Generated_At_UTC,
Generated_By
```

The physical CSV should contain the headings on one line without the visual line breaks shown above.

### Column definitions

| Column | Source |
|---|---|
| `Instruction_ID` | Deterministic display identifier, such as `FIN-<Lien Id suffix>-<timestamp>` |
| `Settlement` | `Settlement__r.Name` |
| `Lien_ID` | Salesforce `Lien__c.Id` |
| `Claimant_ID` | `Claimant_ID__c` |
| `Claimant_Name` | `Claimant_Name__c` |
| `Agreed_Amount` | `Agreed_Amount__c`, two decimals |
| `Recovery_Amount` | `Recovery_Amount__c`, two decimals |
| `Remittance_Amount` | `Remittance_Amount__c`, two decimals |
| `Payment_Variance` | `Payment_Variance__c`, two decimals |
| `Health_Plan_Allocation` | `Health_Plan_Allocation__c`, two decimals |
| `Rawlings_Allocation` | `Rawlings_Allocation__c`, two decimals |
| `Disbursement_Status` | `Disbursement_Status__c` |
| `Generated_At_UTC` | ISO-8601 UTC timestamp |
| `Generated_By` | Current user’s name |

### CSV escaping

The generator must:

- Represent null text as blank.
- Enclose every text value in double quotes.
- Escape embedded double quotes by doubling them.
- Format currency with exactly two decimal places and no currency symbol.
- Use a locale-independent decimal point.

## 9. Eligibility validation

The Apex method must reject generation unless all of these are true:

1. Lien Stage is `Closed`.
2. Disbursement Status is `Approved`.
3. Agreed, recovery, remittance, and allocation amounts are populated.
4. Amounts are non-negative.
5. Payment Variance equals zero.
6. Health Plan Allocation plus Rawlings Allocation equals Remittance Amount.

For currency comparison, use an explicit two-decimal comparison or a tolerance no greater than `$0.01`.

### Error messages

Return business-readable errors:

| Condition | Message |
|---|---|
| Stage not Closed | `Close the lien before generating a Finance instruction.` |
| Disbursement not approved | `Approve the disbursement before generating a Finance instruction.` |
| Missing financial value | `Complete all recovery, remittance, and allocation amounts before generating the instruction.` |
| Payment variance | `The remittance does not match the agreed amount. Resolve the payment variance first.` |
| Allocation mismatch | `Health plan and Rawlings allocations must equal the remittance amount.` |
| Missing Lien | `The lien could not be found or you do not have access to it.` |

Do not expose Apex stack traces to the user.

## 10. Apex design

### Class

`FinanceInstructionWriter.cls`

### Method

```apex
@AuraEnabled
public static FinanceInstructionResult generateInstruction(Id lienId)
```

### Result DTO

```apex
public class FinanceInstructionResult {
    @AuraEnabled public String filename;
    @AuraEnabled public Id contentDocumentId;
    @AuraEnabled public Datetime generatedAt;
    @AuraEnabled public String claimantName;
    @AuraEnabled public Decimal agreedAmount;
    @AuraEnabled public Decimal remittanceAmount;
    @AuraEnabled public Decimal healthPlanAllocation;
    @AuraEnabled public Decimal rawlingsAllocation;
}
```

### Processing sequence

1. Validate `lienId`.
2. Query the Lien and Settlement using `WITH USER_MODE` if compatible with the org’s current API/code style.
3. Validate eligibility.
4. Construct the CSV using a dedicated escaping helper.
5. Insert `ContentVersion`:
   - `Title` = filename without `.csv`
   - `PathOnClient` = filename
   - `VersionData` = `Blob.valueOf(csvBody)`
6. Query the inserted `ContentVersion.ContentDocumentId`.
7. Insert `ContentDocumentLink`:
   - `LinkedEntityId` = Lien ID
   - `ContentDocumentId` = generated document ID
   - `ShareType` = `V`
   - `Visibility` = `AllUsers` only if that matches the existing demo’s security choice
8. Update the Lien audit fields.
9. Return the result DTO.

Use one transaction so an audit-field update is not committed without the corresponding File.

### Repeated generation

For the demo, repeated generation is allowed. Each click creates a new timestamped file and updates the three “most recent” audit fields.

Do not overwrite or delete an earlier instruction.

```text

```

Close or retain the modal based on whichever interaction is more reliable in rehearsal. If retained, include a Done button.

#### Error

- Show the business-readable Apex message inside the action.
- Keep a Close button available.
- Do not show a success toast.

## 13. Permission changes

Update `Rawlings_Demo_Access` with:

- Read/Edit on the three audit fields.
- Apex class access for `FinanceInstructionWriter`.
- LWC visibility through the object action.
- ContentVersion/Files access consistent with the existing response-file generator.

For production, generation should be gated by a dedicated custom permission such as:

```text
Generate_Finance_Instructions
```

That permission is optional for today’s demo if it threatens the schedule. Do not claim action-level authorization is implemented if it is only narrated.

## 14. Apex tests

Create:

`FinanceInstructionWriterTest.cls`

### Required test cases

1. **Successful generation**
   - Closed lien
   - Approved disbursement
   - Zero variance
   - Allocations equal remittance
   - Assert ContentVersion exists.
   - Assert ContentDocumentLink points to the Lien.
   - Assert audit fields are populated.
   - Assert result DTO contains the expected filename and amounts.

2. **Lien not closed**
   - Assert business error.
   - Assert no File created.

3. **Disbursement not approved**
   - Assert business error.

4. **Payment variance**
   - Assert generation is rejected.

5. **Allocation mismatch**
   - Assert generation is rejected.

6. **CSV escaping**
   - Use a claimant or settlement name containing a comma and quote.
   - Assert the stored CSV contains correctly escaped text.

7. **Repeated generation**
   - Generate twice.
   - Assert two Files exist.
   - Assert the audit fields reflect the latest generation.

## 15. Acceptance criteria

- [ ] Action appears on a Lien record.
- [ ] Eligible closed lien produces a CSV in one click.
- [ ] CSV uses the required column order.
- [ ] Currency values have two decimals.
- [ ] Text containing commas or quotes is escaped correctly.
- [ ] File is attached to the Lien.
- [ ] Filename includes claimant ID and timestamp.
- [ ] Generated-at, generated-by, and filename fields update.
- [ ] Prior generated files are retained.
- [ ] Ineligible lien produces a clear error and no File.
- [ ] Allocation mismatch prevents generation.
- [ ] Payment variance prevents generation.
- [ ] LWC prevents duplicate clicks while processing.
- [ ] Apex tests pass.
- [ ] Demo user has required permissions.
- [ ] Reset/rehearsal procedure accounts for generated Files.

## 17. Demo click path

1. Complete the guided lien journey.
2. Return to the Lien Record Page.
3. Point to the reconciled amounts and Approved disbursement.
4. Select **Generate Finance Instruction**.
5. Confirm generation.
6. Pause while the success state appears.
7. Point to the allocation summary.

## 18. Talk track

> “Payment has been reconciled and the allocation has been approved. Salesforce is not moving the money; it is controlling the decision that tells Finance how the money should move.”

> “I’ll generate that instruction now.”

After generation:

> “This is the exact downstream artifact: the lien, the reconciled payment, and the approved split between the health plan and Rawlings. It is attached to the lien with the generating user and timestamp, so the instruction does not disappear into somebody’s desktop or email.”

> “For this prototype, the file stops at the Salesforce boundary. In a later phase, the same approved instruction can be delivered to Finance through the selected integration pattern.”

## 19. Reset procedure

Before each rehearsal:

1. Reset the chosen Lien through the existing demo reset process.
2. Clear:
   - `Finance_Instruction_Generated_At__c`
   - `Finance_Instruction_Generated_By__c`
   - `Finance_Instruction_Filename__c`
3. Delete only previously generated demo Files whose names begin with:

```text
Finance_Instruction_<demo claimant ID>_
```

Do not delete unrelated Salesforce Files.

If deletion is inconvenient or risky, leave the files in place and sort the Files related list by Created Date descending. The timestamped filename makes the newest artifact unambiguous.
